# Contributing

Contributions are welcome. Keep changes focused and easy to review.

## Development workflow

1. Fork or branch from `main`.
2. Install the project dependencies and confirm the application starts using the commands documented in `README.md`.
3. Make one logical change per pull request.
4. Run the relevant formatter, linter, and tests before opening the pull request.
5. Describe what changed, why it changed, and how you verified it.

For UI changes, include a screenshot when it makes the behavior easier to review. Avoid committing generated build output, local configuration, credentials, or editor-specific files.

Bug reports should include the operating system, reproduction steps, expected behavior, and actual behavior.
